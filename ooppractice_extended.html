1.2 — Pointers & Memory

▼
Theory

A pointer stores a memory address. & gets address. * dereferences (gets value at address). Double pointers store address of a pointer.

Pointer Basics
C++ 
int x = 42;
int *p = &x;        // p holds address of x
cout << p;          // prints memory address
cout << *p;         // dereference: prints 42
*p = 99;            // changes x to 99 via pointer

// Double pointer
int **pp = &p;      // pp holds address of pointer p
cout << **pp;       // dereference twice: 99

// NULL pointer
int *np = nullptr;  // safe null (C++11)
if (np != nullptr) cout << *np;  // always check before use
Memory Diagram

Q: What is a dangling pointer? A: A pointer pointing to freed/deleted memory. Accessing it causes undefined behavior.
⚠️ int *p = x; — WRONG! Should be: int *p = &x;
💡 & = 'address of'. * = 'value at'. They are opposites.

📗 Week 2 — Classes & Encapsulation

Core OOP concepts: classes, objects, access specifiers, and encapsulation.

2.1 — Encapsulation

▼
Theory

Encapsulation bundles data (variables) and methods together in a class, restricting direct access to data. Data is private; access is via public methods.

Example
C++ 
class BankAccount {
private:          // DATA HIDDEN
    double balance;
    string owner;

public:           // INTERFACE
    BankAccount(string n, double b) : owner(n), balance(b) {}
    
    void deposit(double amount) {
        if(amount > 0) balance += amount;  // validation!
    }
    
    double getBalance() const { return balance; }
};

int main() {
    BankAccount acc("Alice", 1000);
    // acc.balance = -9999;  // ERROR! private — protected
    acc.deposit(500);         // OK — through public method
    cout << acc.getBalance(); // 1500
    return 0;
}
Q: What is encapsulation? A: Binding data and functions together, hiding internal state, exposing controlled public interface.
Q: Benefits of encapsulation? A: Data protection, input validation, easier maintenance, reduced coupling.
💡 Encapsulation = Capsule. Data locked inside; only medicine (methods) comes out controlled.

📙 Week 3 — Constructors & Destructors

Object initialization and cleanup: all constructor types, deep copy, destructors.

3.1 — Constructors

▼
Theory

A constructor is a special member function called automatically when object is created. Same name as class, no return type.

Constructor Types
C++ — All Constructor Types 
// 1. Default Constructor
class Demo {
public:
    Demo() { cout << "Default constructor" << endl; }
};
Demo d;  // calls default constructor

// 2. Parameterized Constructor
class Box {
    int side;
public:
    Box(int s) : side(s) {}  // init list form
};
Box b(5);

// 3. Copy Constructor (DEEP COPY for pointers!)
class Data {
    int *ptr;
public:
    Data(int val) { ptr = new int(val); }
    
    // CORRECT: Deep copy
    Data(const Data &other) {
        ptr = new int(*other.ptr);  // NEW allocation
    }
    
    ~Data() { delete ptr; }
};

// 4. Delegating Constructor (C++11)
class Point {
    int x, y, z;
public:
    Point(int x, int y, int z) : x(x), y(y), z(z) {}
    Point(int x, int y) : Point(x, y, 0) {}  // delegates
    Point(int x) : Point(x, 0, 0) {}         // delegates
};
Q: Shallow vs deep copy? A: Shallow copies pointer value (both share same memory = DANGEROUS). Deep allocates new memory.
⚠️ Not writing deep copy constructor with pointer members → double-free crash!
💡 Copy constructor signature: always const ClassName& other

3.2 — Destructor

▼
Theory

A destructor is called automatically when object goes out of scope or delete is used. Named ~ClassName(), no parameters, no return type.

Example
C++ 
class Resource {
    int *data;
    string name;
public:
    Resource(string n, int val) : name(n) {
        data = new int(val);
        cout << "Created: " << name << endl;
    }
    
    ~Resource() {        // Destructor
        delete data;     // free heap memory
        cout << "Destroyed: " << name << endl;
    }
};

int main() {
    Resource r1("r1", 10);   // Created: r1
    {
        Resource r2("r2", 20); // Created: r2
    }  // r2 out of scope → Destroyed: r2
    return 0;  // Destroyed: r1
}
Q: When is destructor called? A: 1) Object goes out of scope 2) delete called on pointer 3) Program ends
⚠️ Not writing destructor for class with new → memory leak every time!

📕 Week 5 — Static Members & this Pointer

Static variables, static functions, this pointer, inline functions, friend functions.

5.1 — Static Members

▼
Theory

Static members belong to the class, not individual objects. ALL objects share ONE copy of a static variable. Static functions can only access static members (no this pointer).

Example
C++ 
class Counter {
    static int count;   // declaration (shared by all objects)
    int id;
public:
    Counter() { count++; id = count; }
    ~Counter() { count--; }
    
    static int getCount() {  // static function — no 'this'
        return count;
    }
    int getId() const { return id; }
};

int Counter::count = 0;  // DEFINITION outside class — REQUIRED!

int main() {
    cout << Counter::getCount(); // 0
    Counter c1, c2, c3;
    cout << Counter::getCount(); // 3 — all objects share count
    return 0;
}
Q: What is a static member variable? A: Class-level variable shared by ALL objects. ONE copy regardless of how many objects exist.
Q: Can static functions access non-static members? A: No. Static functions have no 'this' pointer, so instance members are inaccessible.
⚠️ Forgetting to define: int Counter::count = 0; outside class → linker error!
💡 Static = Shared. One copy for entire class, not per object.

5.2 — this Pointer

▼
Theory

The this pointer is an implicit pointer present in every non-static member function pointing to the calling object. Used for self-reference, method chaining, and resolving naming conflicts.

Example
C++ 
class Box {
    int width;
public:
    // Resolve naming conflict
    Box(int width) {
        this->width = width;  // this->width = member, width = param
    }
    
    // Return *this for method chaining
    Box& setWidth(int w) {
        this->width = w;
        return *this;
    }
    Box& addWidth(int n) { width += n; return *this; }
    
    // Self-comparison
    bool isSame(const Box &other) const {
        return this == &other;
    }
};

int main() {
    Box b(10);
    b.setWidth(5).addWidth(3);  // method chaining via *this
    return 0;
}
💡 'this' = 'me'. It always points to the current object executing the function.

📓 Week 6 — Object Relationships

Array of objects, composition, aggregation, association.

6.1 — Composition vs Aggregation

▼
Theory

Composition: 'has-a' strong (part dies with whole). Aggregation: 'has-a' weak (part can outlive whole). Association: 'uses-a' (weakest, independent).

Composition Example
C++ 
// COMPOSITION — Heart owned by Person
class Heart {
public:
    void beat() { cout << "lub-dub" << endl; }
};

class Person {
    Heart heart;  // Heart is INSIDE Person — owned
public:
    void live() { heart.beat(); }
    // Heart created when Person created
    // Heart destroyed when Person destroyed
};

// AGGREGATION — Department has Employees (weak)
class Employee {
    string name;
public:
    Employee(string n) : name(n) {}
};

class Department {
    vector<Employee*> staff;  // pointer — employees live outside!
public:
    void addEmployee(Employee *e) { staff.push_back(e); }
    // Department destroyed but employees still exist
};
Relationship Types
Type Meaning Part Lifetime C++ Implementation
Composition Strong has-a Dies with whole Object member (by value)
Aggregation Weak has-a Outlives whole Pointer member
Association uses-a Independent Reference/pointer parameter
Q: Aggregation vs composition? A: Aggregation: weak, parts exist independently. Composition: strong, parts destroyed with whole.

📔 Week 8 — Inheritance

All inheritance types, access effects, constructor order, data hiding.

8.1 — Inheritance Types

▼
Theory

Inheritance allows a derived class to inherit properties from a base class. Types: Single, Multiple, Multilevel, Hierarchical, Hybrid.

Single Inheritance
C++ 
class Animal {           // BASE class
protected:
    string name;
    int age;
public:
    Animal(string n, int a) : name(n), age(a) {}
    void eat() { cout << name << " eats" << endl; }
};

class Dog : public Animal {   // DERIVED class
    string breed;
public:
    Dog(string n, int a, string b)
        : Animal(n, a),    // MUST call base constructor
          breed(b) {}
    
    void bark() { cout << name << " barks!" << endl; }
};

int main() {
    Dog d("Rex", 3, "Labrador");
    d.eat();   // inherited from Animal
    d.bark();  // Dog's own function
    return 0;
}
Inheritance Types
SINGLE: MULTIPLE: MULTILEVEL: HIERARCHICAL: A A B A A | \/ | / | \ B C B B C D | C
Q: Constructor order in inheritance? A: Base constructor called FIRST, then derived. Top-down order.
Q: Destructor order in inheritance? A: Derived destructor FIRST, then base. Bottom-up order (reverse of construction).
⚠️ Not calling base class constructor → compiler calls default. If no default: compile error!
💡 Constructor: Top-Down (Base→Derived). Destructor: Bottom-Up (Derived→Base).

📃 Week 9 — Polymorphism

Function overloading, overriding, early/late binding, compile-time vs runtime.

9.1 — Polymorphism Types

▼
Theory

Polymorphism = 'many forms'. Compile-time: function overloading. Runtime: virtual functions and overriding.

Function Overloading (Compile-time)
C++ 
class Calculator {
public:
    int add(int a, int b) { return a + b; }
    double add(double a, double b) { return a + b; }
    int add(int a, int b, int c) { return a + b + c; }
};

int main() {
    Calculator c;
    cout << c.add(1, 2);         // 3   — int version
    cout << c.add(1.5, 2.5);     // 4.0 — double version
    cout << c.add(1, 2, 3);      // 6   — 3-arg version
    return 0;
}
Function Overriding (Runtime)
C++ 
class Shape {
public:
    virtual void draw() {
        cout << "Drawing Shape" << endl;
    }
    virtual ~Shape() {}  // ALWAYS virtual destructor!
};

class Circle : public Shape {
public:
    void draw() override {  // override keyword verifies
        cout << "Drawing Circle" << endl;
    }
};

int main() {
    Shape *s = new Circle();
    s->draw();  // Calls Circle::draw (runtime dispatch via vtable)
    delete s;
    return 0;
}
Overloading vs Overriding
Feature Overloading Overriding
Where Same class Base + Derived class
Parameters Must differ Must be identical
virtual needed? No Yes (for polymorphism)
Binding Early (compile-time) Late (runtime)
Q: Overloading vs overriding? A: Overloading: same name, different params, compile-time. Overriding: same params, derived class, runtime.
💡 OverLoad = stack up. OverRide = replace the base version.

10.2 — Binary Arithmetic Operators: + − * / %

▼
Theory

Binary operators take two operands. Use member form when the left operand is your class; use friend/non-member form when the left operand is a built-in type (like double * Vec2).

Full Example — Vec2
C++
#include <iostream>
using namespace std;

// A 2D Vector class demonstrating ALL arithmetic binary operators
class Vec2 {
public:
    double x, y;

    // Default + parameterized constructor
    Vec2(double x = 0.0, double y = 0.0) : x(x), y(y) {}

    // ── BINARY + ──────────────────────────────────────────────
    // Member form: left operand is implicitly *this
    Vec2 operator+(const Vec2& rhs) const {
        return Vec2(x + rhs.x, y + rhs.y);
    }

    // ── BINARY - ──────────────────────────────────────────────
    Vec2 operator-(const Vec2& rhs) const {
        return Vec2(x - rhs.x, y - rhs.y);
    }

    // ── BINARY * (scalar multiply) ────────────────────────────
    // Vec2 * double  — member form
    Vec2 operator*(double s) const {
        return Vec2(x * s, y * s);
    }

    // double * Vec2  — must be friend (left operand is double, not Vec2)
    friend Vec2 operator*(double s, const Vec2& v) {
        return Vec2(v.x * s, v.y * s);   // reuse member version
    }

    // ── BINARY / ──────────────────────────────────────────────
    Vec2 operator/(double s) const {
        if (s == 0.0) throw runtime_error("Division by zero");
        return Vec2(x / s, y / s);
    }

    // ── BINARY % (component-wise modulo on integers, shown as int Vec) ─
    // (Not typical for Vec2 but shows the syntax pattern)
    // Uncomment if you have an int Vec:
    // Vec2 operator%(int m) const { return Vec2(fmod(x,m), fmod(y,m)); }

    // Display helper
    void print() const {
        cout << "(" << x << ", " << y << ")\n";
    }
};

int main() {
    Vec2 a(3.0, 4.0), b(1.0, 2.0);

    (a + b).print();          // (4, 6)   — operator+
    (a - b).print();          // (2, 2)   — operator-
    (a * 2.0).print();        // (6, 8)   — member operator*
    (3.0 * a).print();        // (9, 12)  — friend operator*
    (a / 2.0).print();        // (1.5, 2) — operator/
    return 0;
}
Q: When should operator+ be a friend vs member?A: Use friend when you need the left operand to be a non-class type (e.g. 3.0 * vec). Member form requires the left side to be the class.
⚠️ Don't modify *this in operator+ — return a new object. (op+= modifies, op+ should not.)

10.3 — Compound Assignment Operators: += −= *= /= %=

▼
Theory

Compound assignment modifies and returns *this by reference. This enables chaining and is more efficient than creating temporaries.

Full Example — Vec2 compound
C++
#include <iostream>
using namespace std;

class Vec2 {
public:
    double x, y;
    Vec2(double x = 0, double y = 0) : x(x), y(y) {}

    // ── COMPOUND ASSIGNMENT: += ───────────────────────────────
    // Returns *this by reference — enables chaining: a += b += c
    Vec2& operator+=(const Vec2& rhs) {
        x += rhs.x;
        y += rhs.y;
        return *this;   // <-- must return reference to self
    }

    // ── COMPOUND ASSIGNMENT: -= ───────────────────────────────
    Vec2& operator-=(const Vec2& rhs) {
        x -= rhs.x;
        y -= rhs.y;
        return *this;
    }

    // ── COMPOUND ASSIGNMENT: *= (scalar) ─────────────────────
    Vec2& operator*=(double s) {
        x *= s;
        y *= s;
        return *this;
    }

    // ── COMPOUND ASSIGNMENT: /= ───────────────────────────────
    Vec2& operator/=(double s) {
        if (s == 0) throw runtime_error("Div by zero");
        x /= s;
        y /= s;
        return *this;
    }

    // ── COMPOUND ASSIGNMENT: %= (integer mod) ────────────────
    // Shown with IntPair for clarity
    void print() const { cout << "(" << x << ", " << y << ")\n"; }
};

int main() {
    Vec2 v(10.0, 20.0);

    v += Vec2(1.0, 2.0);   v.print();   // (11, 22)
    v -= Vec2(1.0, 2.0);   v.print();   // (10, 20)
    v *= 2.0;              v.print();   // (20, 40)
    v /= 4.0;              v.print();   // (5, 10)
    return 0;
}
Q: Why does operator+= return *this by reference?A: Enables chaining (a += b += c) and matches built-in semantics. Returning void would break chained expressions.

10.4 — Relational Operators: == != < > <= >=

▼
Theory

All six comparison operators. Best practice: implement == and <, then express all others in terms of these two to keep logic in one place.

Full Example — Student comparisons
C++
#include <iostream>
using namespace std;

// A Student class demonstrating ALL 6 relational operators
class Student {
public:
    string name;
    double gpa;

    Student(const string& n, double g) : name(n), gpa(g) {}

    // ── EQUALITY: == ──────────────────────────────────────────
    // Friend form: both sides treated symmetrically
    friend bool operator==(const Student& a, const Student& b) {
        return a.gpa == b.gpa && a.name == b.name;
    }

    // ── INEQUALITY: != ────────────────────────────────────────
    // Implement in terms of == (avoid duplication)
    friend bool operator!=(const Student& a, const Student& b) {
        return !(a == b);   // reuse operator==
    }

    // ── LESS THAN: < ──────────────────────────────────────────
    // Used by std::sort, std::map, std::set by default
    friend bool operator<(const Student& a, const Student& b) {
        return a.gpa < b.gpa;   // compare by GPA
    }

    // ── GREATER THAN: > ───────────────────────────────────────
    // Implement in terms of < (avoid duplication)
    friend bool operator>(const Student& a, const Student& b) {
        return b < a;           // flip: b < a is same as a > b
    }

    // ── LESS THAN OR EQUAL: <= ───────────────────────────────
    friend bool operator<=(const Student& a, const Student& b) {
        return !(a > b);        // not greater means <=
    }

    // ── GREATER THAN OR EQUAL: >= ─────────────────────────────
    friend bool operator>=(const Student& a, const Student& b) {
        return !(a < b);        // not less means >=
    }
};

int main() {
    Student alice("Alice", 3.8), bob("Bob", 3.5);

    cout << (alice == bob)  << "\n";   // 0 (false) — different gpa
    cout << (alice != bob)  << "\n";   // 1 (true)
    cout << (alice > bob)   << "\n";   // 1 (true)  — 3.8 > 3.5
    cout << (alice < bob)   << "\n";   // 0 (false)
    cout << (alice >= bob)  << "\n";   // 1 (true)
    cout << (alice <= bob)  << "\n";   // 0 (false)
    return 0;
}
Q: Why implement > as 'return b < a' instead of a > b?A: Avoids code duplication. Only operator< needs the actual comparison logic; all others derive from it.
💡 Golden rule: implement == and <. Express !=, >, <=, >= in terms of those two.

10.5 — Unary Operators: ++ −− − + ! ~

▼
Theory

Unary operators act on a single operand. The dummy int parameter distinguishes postfix from prefix. Prefix returns *this by reference (more efficient); postfix returns a value copy of the old state.

Full Example — Counter all unary ops
C++
#include <iostream>
using namespace std;

class Counter {
    int val;
public:
    Counter(int v = 0) : val(v) {}
    int get() const { return val; }

    // ── PREFIX ++counter ──────────────────────────────────────
    // Increments FIRST, then returns new (modified) value
    // Returns reference — enables ++(++c)
    Counter& operator++() {
        ++val;
        return *this;
    }

    // ── POSTFIX counter++ ─────────────────────────────────────
    // Saves OLD value, increments, returns OLD copy
    // Dummy int parameter distinguishes from prefix
    // Returns value (not reference) — old copy would be dangling ref
    Counter operator++(int) {
        Counter old = *this;    // snapshot before increment
        ++val;                  // now increment
        return old;             // return the OLD snapshot
    }

    // ── PREFIX --counter ──────────────────────────────────────
    Counter& operator--() {
        --val;
        return *this;
    }

    // ── POSTFIX counter-- ─────────────────────────────────────
    Counter operator--(int) {
        Counter old = *this;
        --val;
        return old;
    }

    // ── UNARY MINUS: -counter ─────────────────────────────────
    // Returns negated copy (does NOT modify this)
    Counter operator-() const {
        return Counter(-val);
    }

    // ── UNARY PLUS: +counter ──────────────────────────────────
    // Returns copy unchanged (rarely useful but valid)
    Counter operator+() const {
        return Counter(+val);
    }

    // ── LOGICAL NOT: !counter ─────────────────────────────────
    // True when counter is zero
    bool operator!() const {
        return val == 0;
    }

    // ── BITWISE NOT: ~counter ─────────────────────────────────
    Counter operator~() const {
        return Counter(~val);
    }
};

int main() {
    Counter c(5);

    cout << (++c).get() << "\n";   // 6   — prefix: increment then return
    cout << (c++).get() << "\n";   // 6   — postfix: return old, then increment
    cout << c.get()     << "\n";   // 7   — now 7 after postfix

    cout << (--c).get() << "\n";   // 6   — prefix decrement
    cout << (c--).get() << "\n";   // 6   — postfix: return old (6), then 5
    cout << c.get()     << "\n";   // 5   — now 5

    cout << (-c).get()  << "\n";   // -5  — unary minus
    cout << (!c)        << "\n";   // 0   — 5 != 0 so !c is false

    Counter z(0);
    cout << (!z)        << "\n";   // 1   — 0 == 0 so !z is true
    return 0;
}
Q: Why does postfix operator++ return by value, not reference?A: It returns a temporary (old copy). A reference to a local variable would be dangling after the function returns.
Q: When is prefix ++ preferred over postfix?A: Always, when both are equivalent — prefix avoids creating a temporary copy.

10.6 — Copy Assignment Operator =

▼
Theory

The assignment operator must be a non-static member function (language rule). When your class owns heap memory, implement the Rule of Three: destructor + copy constructor + copy assignment.

Full Example — MyString deep copy
C++
#include <iostream>
#include <cstring>
using namespace std;

// A dynamic string class showing the full Rule of Three
class MyString {
    char* data;     // pointer — requires deep copy!
    int   len;
public:
    // ── CONSTRUCTOR ───────────────────────────────────────────
    MyString(const char* s = "") {
        len  = strlen(s);
        data = new char[len + 1];   // allocate on heap
        strcpy(data, s);
    }

    // ── COPY CONSTRUCTOR ──────────────────────────────────────
    // Called when: MyString b = a;  or  passing by value
    MyString(const MyString& other) {
        len  = other.len;
        data = new char[len + 1];   // own allocation — deep copy!
        strcpy(data, other.data);
    }

    // ── COPY ASSIGNMENT OPERATOR = ────────────────────────────
    // Called when: b = a;  (both already exist)
    // Must be a NON-STATIC MEMBER — language requirement
    MyString& operator=(const MyString& other) {
        // STEP 1: Self-assignment guard (a = a must be a no-op)
        if (this == &other) return *this;

        // STEP 2: Free existing resource
        delete[] data;

        // STEP 3: Allocate new and copy
        len  = other.len;
        data = new char[len + 1];
        strcpy(data, other.data);

        // STEP 4: Return *this to allow chaining (a = b = c)
        return *this;
    }

    // ── DESTRUCTOR ────────────────────────────────────────────
    ~MyString() {
        delete[] data;   // free heap memory
    }

    void print() const { cout << data << "\n"; }
};

int main() {
    MyString s1("Hello");
    MyString s2("World");

    s2 = s1;             // calls operator= (copy assignment)
    s2.print();          // Hello

    s1 = s1;             // self-assignment — guard prevents crash
    s1.print();          // Hello (unchanged)

    MyString s3("A"), s4("B"), s5("C");
    s3 = s4 = s5;        // chaining: s4=s5 returns s4, then s3=s4
    s3.print();          // C
    s4.print();          // C
    return 0;
}
Q: What are the four steps of a correct operator=?A: (1) Self-assignment guard if(this!=&other), (2) free old resource, (3) allocate and copy new, (4) return *this.
⚠️ Forgetting self-assignment guard: a = a would delete data before copying, causing UB!

10.7 — Stream Output Operator <<

▼
Theory

operator<< is the insertion operator. The left operand is ostream (like cout), so it cannot be a member function of your class. It must be a friend or free function. Always return ostream& to enable chaining.

Full Example — Point output
C++
#include <iostream>
#include <string>
using namespace std;

// Demonstrating operator<< (insertion / output stream)
class Point {
public:
    double x, y, z;
    Point(double x = 0, double y = 0, double z = 0) : x(x), y(y), z(z) {}

    // ── operator<< — MUST be a friend (or non-member) ────────
    // Why? Left operand is ostream, NOT Point.
    // Member function: Point.operator<<(ostream) — impossible (left must be Point)
    // Solution: friend gives access to private members
    //
    // ostream& return type — enables CHAINING: cout << p1 << p2 << endl
    friend ostream& operator<<(ostream& out, const Point& p) {
        out << "Point(" << p.x << ", " << p.y << ", " << p.z << ")";
        return out;   // <-- must return out for chaining
    }
};

int main() {
    Point a(1.0, 2.0, 3.0);
    Point b(4.0, 5.0, 6.0);

    cout << a << "\n";          // Point(1, 2, 3)
    cout << a << " and " << b;  // chaining works — both print

    // Writing to a file stream (same operator, different stream)
    // ofstream file("out.txt");
    // file << a;               // works with any ostream subclass
    return 0;
}
Q: Why must operator<< be a friend?A: The left operand is ostream (cout), not your class. A member function would require your class on the left: Point.operator<<(cout) makes no sense syntactically.
💡 ostream& return = chain enabler. Always: 'out << ... ; return out;'

10.8 — Stream Input Operator >>

▼
Theory

operator>> is the extraction operator. Same rule as <<: left operand is istream, so it must be a friend. The right operand is taken by non-const reference (you modify it). Returns istream& for chaining.

Full Example — Point input
C++
#include <iostream>
#include <string>
using namespace std;

class Point {
public:
    double x, y, z;
    Point(double x = 0, double y = 0, double z = 0) : x(x), y(y), z(z) {}

    // ── operator<< (output) ───────────────────────────────────
    friend ostream& operator<<(ostream& out, const Point& p) {
        out << "(" << p.x << ", " << p.y << ", " << p.z << ")";
        return out;
    }

    // ── operator>> — MUST be friend or non-member ────────────
    // Left operand is istream, NOT Point.
    // Takes Point by NON-CONST reference (we modify it).
    // Returns istream& for chaining: cin >> a >> b
    friend istream& operator>>(istream& in, Point& p) {
        cout << "Enter x y z: ";
        in >> p.x >> p.y >> p.z;   // read three doubles
        return in;                  // return stream for chaining
    }
};

int main() {
    Point p;
    cin >> p;          // calls operator>> — reads from stdin
    cout << p << "\n"; // calls operator<< — prints to stdout

    // Chaining input (reads two Points in sequence)
    Point q, r;
    cin >> q >> r;
    cout << q << " and " << r << "\n";
    return 0;
}
Q: Difference between operator<< and operator>>?A: Both are friends (left is stream not your class). << takes const ref (read-only), >> takes non-const ref (to fill it). << returns ostream&, >> returns istream&.
⚠️ Taking Point by const reference in operator>> — you can't modify it to store the input!

10.9 — Subscript Operator []

▼
Theory

operator[] must be a member. Always provide two versions: a non-const version returning T& (for writing), and a const version returning const T& (for reading from const objects).

Full Example — SafeArray with bounds checking
C++
#include <iostream>
using namespace std;

// A safe fixed-size array wrapper using operator[]
class SafeArray {
    int* data;
    int  size_;
public:
    SafeArray(int n) : size_(n) {
        data = new int[n]();   // zero-initialize
    }

    ~SafeArray() { delete[] data; }

    // ── operator[] — NON-CONST version (for writing) ─────────
    // Returns int& so caller can do: arr[i] = 42;
    int& operator[](int i) {
        if (i < 0 || i >= size_)
            throw out_of_range("Index out of range");
        return data[i];
    }

    // ── operator[] — CONST version (for reading from const obj)
    // Required if you ever pass SafeArray as const reference
    const int& operator[](int i) const {
        if (i < 0 || i >= size_)
            throw out_of_range("Index out of range");
        return data[i];
    }

    int size() const { return size_; }
};

int main() {
    SafeArray arr(5);

    // Write via non-const operator[]
    for (int i = 0; i < 5; i++)
        arr[i] = i * 10;   // arr[i] returns int& — assignment works

    // Read via non-const operator[]
    for (int i = 0; i < 5; i++)
        cout << arr[i] << " ";   // 0 10 20 30 40
    cout << "\n";

    // Test bounds checking
    try {
        arr[10] = 999;   // throws out_of_range
    } catch (const out_of_range& e) {
        cout << "Error: " << e.what() << "\n";
    }

    // Const object uses const operator[]
    const SafeArray cArr(cArr);   // const reference scenario
    return 0;
}
Q: Why two versions of operator[]?A: The const version is called when your object is const or passed as const reference. Without it, const objects cannot use [] at all.

10.10 — Function Call Operator () — Functors

▼
Theory

operator() makes your object callable like a function. These are called functors (function objects). They are stateful (unlike raw functions) and can carry configuration. They are the foundation of callbacks and custom sorting.

Full Example — Multiplier, Adder, Comparator
C++
#include <iostream>
using namespace std;

// A Multiplier functor — operator() makes an object callable like a function
class Multiplier {
    double factor;
public:
    // Constructor stores the factor
    explicit Multiplier(double f) : factor(f) {}

    // ── operator() — makes object callable ───────────────────
    // obj(arg) calls operator()(arg)
    double operator()(double x) const {
        return x * factor;
    }
};

// A stateful Adder — accumulates totals
class Adder {
    double total;
public:
    Adder() : total(0.0) {}

    // Callable: add a value and return running total
    double operator()(double x) {
        total += x;
        return total;
    }

    double getTotal() const { return total; }
};

// A Comparator functor — used for custom sorting
class ByAbsValue {
public:
    // Returns true if |a| < |b|
    bool operator()(int a, int b) const {
        return (a < 0 ? -a : a) < (b < 0 ? -b : b);
    }
};

int main() {
    Multiplier triple(3.0);
    cout << triple(5.0)  << "\n";   // 15   — triple(5) calls operator()(5)
    cout << triple(2.5)  << "\n";   // 7.5

    Adder acc;
    cout << acc(10.0)    << "\n";   // 10   — running total
    cout << acc(20.0)    << "\n";   // 30
    cout << acc(5.0)     << "\n";   // 35
    cout << acc.getTotal() << "\n"; // 35

    // Sorting with a comparator functor
    int arr[] = {-5, 2, -3, 8, -1};
    int n = 5;
    // Bubble sort using functor
    ByAbsValue cmp;
    for (int i = 0; i < n-1; i++)
        for (int j = 0; j < n-i-1; j++)
            if (!cmp(arr[j], arr[j+1])) {
                int tmp = arr[j]; arr[j] = arr[j+1]; arr[j+1] = tmp;
            }
    for (int i = 0; i < n; i++)
        cout << arr[i] << " ";   // -1 2 -3 -5 8 (sorted by |value|)
    cout << "\n";
    return 0;
}
Q: Functor vs regular function?A: Functors are objects — they carry state (like the factor in Multiplier). A plain function can't hold configuration between calls.
💡 Functor = function + state. Perfect for custom sort comparators and callbacks.

10.11 — Arrow Operator -> (Smart Pointer Pattern)

▼
Theory

operator-> must be a member. It must return a raw pointer (or an object that itself has ->). The compiler auto-applies -> to the returned value, so smartPtr->fn() becomes smartPtr.operator->()->fn().

Full Example — SmartPtr with ->
C++
#include <iostream>
#include <string>
using namespace std;

// A minimal smart pointer — wraps a raw pointer
// operator-> makes it behave like a pointer
template <typename T>
class SmartPtr {
    T* ptr;
public:
    // Takes ownership of raw pointer
    explicit SmartPtr(T* p) : ptr(p) {}

    // ── operator-> — gives pointer-like access ────────────────
    // Must be a member; return type must be a pointer or something with ->
    // Enables: smartPtr->memberFunction()
    T* operator->() {
        if (!ptr) throw runtime_error("Null pointer dereference");
        return ptr;   // compiler then applies -> to returned raw ptr
    }

    // ── operator* — dereference ───────────────────────────────
    T& operator*() {
        if (!ptr) throw runtime_error("Null dereference");
        return *ptr;
    }

    // Destructor — auto-delete on scope exit
    ~SmartPtr() { delete ptr; }
};

struct Person {
    string name;
    int    age;
    Person(const string& n, int a) : name(n), age(a) {}
    void greet() const { cout << "Hi, I'm " << name << " age " << age << "\n"; }
};

int main() {
    SmartPtr<Person> p(new Person("Alice", 30));

    p->greet();                      // SmartPtr::operator-> returns raw ptr, then ->greet()
    cout << (*p).name << "\n";       // dereference then member access
    cout << p->age    << "\n";       // 30

    // When p goes out of scope: ~SmartPtr() calls delete ptr — no leak
    return 0;
}
Q: What must operator-> return?A: A raw pointer (or object with operator->). The compiler recursively applies -> until it gets a raw pointer.

10.12 — Type Conversion Operators

▼
Theory

Type conversion operators let your class be implicitly or explicitly cast to another type. Syntax: operator TargetType() const. Use explicit to require a cast and prevent accidental conversions.

Full Example — Fraction → double, string, bool
C++
#include <iostream>
#include <string>
using namespace std;

// Type conversion operators: allow your class to be implicitly/explicitly
// converted to another type
class Fraction {
    int num, den;
public:
    Fraction(int n, int d) : num(n), den(d) {
        if (d == 0) throw invalid_argument("Denominator cannot be zero");
    }

    // ── CONVERSION TO double ──────────────────────────────────
    // operator double() lets compiler convert Fraction -> double automatically
    // Syntax: operator <targetType>() const { return <value>; }
    operator double() const {
        return static_cast<double>(num) / den;
    }

    // ── CONVERSION TO string (explicit) ───────────────────────
    // 'explicit' prevents accidental implicit conversion
    // Must use: static_cast<string>(f)  or  string(f)
    explicit operator string() const {
        return to_string(num) + "/" + to_string(den);
    }

    // ── CONVERSION TO bool ────────────────────────────────────
    // Common pattern: is the value non-zero?
    explicit operator bool() const {
        return num != 0;
    }

    void print() const { cout << num << "/" << den; }
};

int main() {
    Fraction half(1, 2);
    Fraction zero(0, 5);

    // Implicit: operator double()
    double d = half;             // 0.5 — implicit conversion
    cout << d << "\n";

    // In expression — auto-converts
    cout << (half + 1.5) << "\n"; // 2.0  — half becomes 0.5

    // Explicit: operator string()
    string s = static_cast<string>(half);
    cout << s << "\n";            // 1/2

    // Explicit: operator bool()
    if (half)  cout << "half is non-zero\n";    // prints
    if (!zero) cout << "zero is zero\n";        // prints

    return 0;
}
Q: What is 'explicit' on a conversion operator?A: Prevents implicit conversion. Without it, Fraction could silently become double anywhere, causing subtle bugs.
💡 operator bool() is the most common — lets you do: if (myObject) { ... }

10.13 — Bitwise Operators: & | ^ ~ << >>

▼
Theory

All six bitwise operators can be overloaded. Common use case: bit-flag classes, bitmasks, permissions. Note that << and >> used as stream operators have nothing to do with bit shifting — the context determines which overload is called.

Full Example — Flags class all bitwise ops
C++
#include <iostream>
using namespace std;

// A Flags class demonstrating ALL bitwise operators
// Useful pattern: bit flags, permissions, masks
class Flags {
    unsigned int bits;
public:
    explicit Flags(unsigned int v = 0) : bits(v) {}
    unsigned int value() const { return bits; }

    // ── BITWISE AND: & ────────────────────────────────────────
    // a & b — bit is 1 only if both bits are 1
    Flags operator&(const Flags& rhs) const {
        return Flags(bits & rhs.bits);
    }
    Flags& operator&=(const Flags& rhs) {
        bits &= rhs.bits;
        return *this;
    }

    // ── BITWISE OR: | ─────────────────────────────────────────
    // a | b — bit is 1 if either bit is 1 (set a flag)
    Flags operator|(const Flags& rhs) const {
        return Flags(bits | rhs.bits);
    }
    Flags& operator|=(const Flags& rhs) {
        bits |= rhs.bits;
        return *this;
    }

    // ── BITWISE XOR: ^ ────────────────────────────────────────
    // a ^ b — bit is 1 if bits DIFFER (toggle a flag)
    Flags operator^(const Flags& rhs) const {
        return Flags(bits ^ rhs.bits);
    }
    Flags& operator^=(const Flags& rhs) {
        bits ^= rhs.bits;
        return *this;
    }

    // ── BITWISE NOT: ~ ────────────────────────────────────────
    // ~a — flip all bits
    Flags operator~() const {
        return Flags(~bits);
    }

    // ── LEFT SHIFT: << ────────────────────────────────────────
    // a << n — shift bits left by n (multiply by 2^n)
    Flags operator<<(int n) const {
        return Flags(bits << n);
    }
    Flags& operator<<=(int n) {
        bits <<= n;
        return *this;
    }

    // ── RIGHT SHIFT: >> ───────────────────────────────────────
    // a >> n — shift bits right by n (divide by 2^n)
    Flags operator>>(int n) const {
        return Flags(bits >> n);
    }
    Flags& operator>>=(int n) {
        bits >>= n;
        return *this;
    }

    void print(const char* label) const {
        cout << label << ": " << bits << " (0b";
        for (int i = 7; i >= 0; i--)
            cout << ((bits >> i) & 1);
        cout << ")\n";
    }
};

int main() {
    Flags a(0b00001111);   // 15
    Flags b(0b11110000);   // 240

    (a & b).print("a & b");    // 0b00000000 — no overlap
    (a | b).print("a | b");    // 0b11111111 — all bits
    (a ^ b).print("a ^ b");    // 0b11111111 — all differ
    (~a).print("~a");           // 0b11110000 — flipped

    Flags c(0b00000001);   // 1
    (c << 3).print("c << 3");  // 0b00001000 = 8
    (c >> 0).print("c >> 0");  // unchanged

    return 0;
}
Q: Is bitwise << the same as stream <A: No. They share the same symbol but are completely different overloads selected by the types of the operands (ostream vs your class).

10.14 — Logical Operators: && || !

▼
Theory

All three logical operators are overloadable. ! is safe to overload. Warning: overloading && and || destroys short-circuit evaluation — both operands are always evaluated, unlike built-in &&/||.

Full Example — Three-valued logic
C++
#include <iostream>
using namespace std;

// Logical AND (&&) and OR (||) can be overloaded but doing so LOSES
// short-circuit evaluation — the built-in && stops at first false.
// Shown here for completeness with the caveat clearly documented.

class Tri {
    int val;   // -1 = false, 0 = unknown, 1 = true (three-valued logic)
public:
    explicit Tri(int v) : val(v) {}
    int get() const { return val; }

    // ── LOGICAL NOT: ! ────────────────────────────────────────
    // Safe to overload; no short-circuit issue
    Tri operator!() const {
        return Tri(-val);   // true→false, false→true, unknown→unknown
    }

    // ── LOGICAL AND: && ──────────────────────────────────────
    // WARNING: No short-circuit! Both operands ALWAYS evaluated.
    // (Built-in && stops if left is false — overloaded version cannot)
    Tri operator&&(const Tri& rhs) const {
        if (val == -1 || rhs.val == -1) return Tri(-1);  // false
        if (val ==  1 && rhs.val ==  1) return Tri( 1);  // true
        return Tri(0);                                    // unknown
    }

    // ── LOGICAL OR: || ───────────────────────────────────────
    // WARNING: No short-circuit! Same caveat as &&.
    Tri operator||(const Tri& rhs) const {
        if (val ==  1 || rhs.val ==  1) return Tri(1);   // true
        if (val == -1 && rhs.val == -1) return Tri(-1);  // false
        return Tri(0);                                    // unknown
    }

    const char* str() const {
        return val == 1 ? "true" : (val == -1 ? "false" : "unknown");
    }
};

int main() {
    Tri T(1), F(-1), U(0);

    cout << (T && F).str() << "\n";  // false
    cout << (T && U).str() << "\n";  // unknown
    cout << (T || F).str() << "\n";  // true
    cout << (F || U).str() << "\n";  // unknown
    cout << (!T).str()     << "\n";  // false
    cout << (!F).str()     << "\n";  // true
    return 0;
}
Q: Why avoid overloading && and ||?A: Built-in short-circuit eval stops evaluation early (right side not computed if result known from left). Overloaded versions always evaluate both sides — behavior change can introduce bugs.
⚠️ Overloading && or || for a class that has side effects on evaluation — short-circuit is lost!

10.15 — Memory Operators: new delete new[] delete[]

▼
Theory

Memory operators can be overloaded per-class to implement custom memory pools, memory tracking, or specialized alignment. They are implicitly static. operator new allocates raw memory; the constructor is called separately by the compiler.

Full Example — Tracked class with all 4 memory ops
C++
#include <iostream>
#include <cstdlib>   // malloc, free
using namespace std;

// Overloading global new/delete for a specific class
// Useful for: custom memory pools, tracking allocations, alignment

class Tracked {
    static int count;
    int id;
public:
    Tracked() : id(++count) {
        cout << "Constructing object #" << id << "\n";
    }

    ~Tracked() {
        cout << "Destroying object #" << id << "\n";
    }

    // ── OVERLOAD operator new ─────────────────────────────────
    // Called when: Tracked* p = new Tracked;
    // Must be STATIC (implicitly) — no 'this' pointer yet
    // Must return void*
    static void* operator new(size_t size) {
        cout << "Custom new: allocating " << size << " bytes\n";
        void* ptr = malloc(size);
        if (!ptr) throw bad_alloc();
        return ptr;
    }

    // ── OVERLOAD operator delete ──────────────────────────────
    // Called when: delete p;
    // Must be STATIC (implicitly)
    static void operator delete(void* ptr) {
        cout << "Custom delete: freeing memory\n";
        free(ptr);
    }

    // ── OVERLOAD operator new[] ───────────────────────────────
    // Called when: Tracked* arr = new Tracked[5];
    static void* operator new[](size_t size) {
        cout << "Custom new[]: allocating " << size << " bytes\n";
        void* ptr = malloc(size);
        if (!ptr) throw bad_alloc();
        return ptr;
    }

    // ── OVERLOAD operator delete[] ────────────────────────────
    // Called when: delete[] arr;
    static void operator delete[](void* ptr) {
        cout << "Custom delete[]: freeing array\n";
        free(ptr);
    }

    static int getCount() { return count; }
};

int Tracked::count = 0;

int main() {
    Tracked* a = new Tracked;     // Custom new → constructor
    Tracked* b = new Tracked;     // Custom new → constructor
    delete a;                     // destructor → Custom delete
    delete b;

    Tracked* arr = new Tracked[3]; // Custom new[] → 3 constructors
    delete[] arr;                  // 3 destructors → Custom delete[]
    return 0;
}
Q: What does operator new return?A: void* — raw uninitialized memory. The compiler then calls the constructor on that memory separately.
💡 new = malloc + constructor call. delete = destructor call + free. You override the malloc/free part only.

10.16 — Comma Operator ,

▼
Theory

The comma operator is almost never overloaded in practice, but can be. Built-in: evaluates left expression (result discarded), then evaluates and returns right. Overloaded version loses the sequencing guarantee.

Comma operator example
C++
#include <iostream>
using namespace std;

// The comma operator is rarely overloaded, but here's the pattern.
// In C++, the built-in comma operator: evaluate left, discard, return right.
class Token {
    int val;
public:
    explicit Token(int v) : val(v) {}
    int get() const { return val; }

    // ── COMMA OPERATOR , ──────────────────────────────────────
    // Called for: t1, t2  — evaluates both, returns rhs
    // WARNING: overloading comma is almost always a bad idea in practice.
    // It is done here purely for educational completeness.
    Token operator,(const Token& rhs) const {
        cout << "[comma: evaluated " << val << " and " << rhs.val << "]\n";
        return rhs;  // built-in comma returns right operand
    }
};

int main() {
    Token a(1), b(2), c(3);
    Token result = (a, b, c);   // calls operator, twice
    // Output: [comma: evaluated 1 and 2]
    //         [comma: evaluated 2 and 3]
    cout << "result: " << result.get() << "\n";   // 3

    // In a for loop (built-in comma still works in init/increment)
    for (int i = 0, j = 10; i < 3; ++i, --j)
        cout << i << " " << j << "\n";   // uses built-in comma, not overloaded
    return 0;
}
Q: Should you overload operator,?A: Almost never. It destroys sequencing guarantees and confuses readers. The only legitimate use case is expression templates in advanced template metaprogramming.

10.17 — Dereference * and Iterator Pattern

▼
Theory

Combining operator*, operator++, and operator!= gives you a full iterator. This is how all standard library iterators work internally. The iterator pattern is the most practical use of multiple operator overloads together.

Full Example — ArrayIter custom iterator
C++
#include <iostream>
using namespace std;

// Iterator pattern — demonstrates operator* and operator->
// A simple iterator over a fixed-size int array
class ArrayIter {
    int* ptr;
public:
    explicit ArrayIter(int* p) : ptr(p) {}

    // ── DEREFERENCE: *iter ────────────────────────────────────
    // Returns reference so you can modify: *iter = 42;
    int& operator*() {
        return *ptr;
    }

    // Const version — for read-only iterators
    const int& operator*() const {
        return *ptr;
    }

    // ── PREFIX ++iter (advance iterator) ─────────────────────
    ArrayIter& operator++() {
        ++ptr;
        return *this;
    }

    // ── POSTFIX iter++ ────────────────────────────────────────
    ArrayIter operator++(int) {
        ArrayIter old = *this;
        ++ptr;
        return old;
    }

    // ── EQUALITY (to detect end) ──────────────────────────────
    bool operator==(const ArrayIter& o) const { return ptr == o.ptr; }
    bool operator!=(const ArrayIter& o) const { return ptr != o.ptr; }

    // ── RANDOM ACCESS: iter + n ───────────────────────────────
    ArrayIter operator+(int n) const { return ArrayIter(ptr + n); }

    // ── SUBSCRIPT: iter[n] ────────────────────────────────────
    int& operator[](int n) { return ptr[n]; }
};

int main() {
    int arr[] = {10, 20, 30, 40, 50};
    ArrayIter it(arr);
    ArrayIter end(arr + 5);

    // Range loop using custom iterator
    for (ArrayIter i = it; i != end; ++i) {
        cout << *i << " ";       // 10 20 30 40 50
    }
    cout << "\n";

    // Modify through dereference
    *it = 99;
    cout << arr[0] << "\n";     // 99 — modified in place

    // Subscript via iterator
    cout << it[2]  << "\n";     // 30 (arr[2])

    return 0;
}
Q: What minimum operators does a forward iterator need?A: operator* (dereference), operator++ (advance), operator== / operator!= (termination check).
💡 Iterator = operator* + operator++ + operator!=. These three unlock range-based for loops.

11.1 — Diamond Problem Solution

▼
Theory

The diamond problem occurs when two parents inherit the same grandparent, creating ambiguous duplicate copies. Solved with virtual inheritance.

Diamond Fix with Virtual Inheritance
C++ 
// WITHOUT virtual — PROBLEM:
// class Hybrid : public Dog, public Cat { };
// Hybrid h;
// h.breathe();  // ERROR: which Animal::breathe? Ambiguous!

// WITH virtual — SOLUTION:
class Animal {
public:
    string name;
    Animal(string n = "") : name(n) {}
    void breathe() { cout << name << " breathes\n"; }
};

class Dog : virtual public Animal {
public:
    Dog(string n) : Animal(n) {}
    void bark() { cout << name << " barks\n"; }
};

class Cat : virtual public Animal {
public:
    Cat(string n) : Animal(n) {}
    void meow() { cout << name << " meows\n"; }
};

class Hybrid : public Dog, public Cat {
public:
    // MOST DERIVED must call virtual base!
    Hybrid(string n) : Animal(n), Dog(n), Cat(n) {}
};

    Hybrid h("Hyby");
    h.breathe();  // OK — only ONE Animal copy
    h.bark();
    h.meow();
    return 0;
}

Q: Who calls virtual base constructor? A: The MOST DERIVED class must explicitly call it.

16.1 — Exception Handling: try / catch / throw / rethrow

▼
Theory

Exception handling separates error detection from error recovery. Use it for errors that cannot be handled locally. throw sends the exception object up the call stack; catch receives it.

Basic & Multiple Catch & Rethrow
C++
#include <iostream>
#include <stdexcept>
using namespace std;

// ── BASIC TRY-CATCH ───────────────────────────────────────────────────────
// try   = enclose risky code
// throw = signal that something went wrong (can throw any type)
// catch = handle the thrown exception

int divide(int a, int b) {
    if (b == 0)
        throw runtime_error("Division by zero");   // throw an exception object
    return a / b;
}

int main() {
    // ── SINGLE CATCH ──────────────────────────────────────────
    try {
        int result = divide(10, 0);   // throws runtime_error
        cout << result;               // never reached
    }
    catch (const runtime_error& e) {  // catch by CONST REFERENCE — prevents slicing
        cout << "Caught: " << e.what() << "\n";
    }

    // ── MULTIPLE CATCH (ordered specific → general) ───────────
    try {
        throw out_of_range("Index 99 is out of bounds");
    }
    catch (const out_of_range& e) {      // most specific first
        cout << "Range error: " << e.what() << "\n";
    }
    catch (const invalid_argument& e) {  // other std exceptions
        cout << "Invalid arg: " << e.what() << "\n";
    }
    catch (const exception& e) {         // base class catches all std exceptions
        cout << "std exception: " << e.what() << "\n";
    }
    catch (...) {                        // catch EVERYTHING (including non-std throws)
        cout << "Unknown exception\n";
    }

    // ── RETHROWING ────────────────────────────────────────────
    try {
        try {
            throw runtime_error("original error");
        }
        catch (const runtime_error& e) {
            cout << "Inner catch: " << e.what() << "\n";
            throw;   // rethrow the SAME exception (no copy made)
        }
    }
    catch (const runtime_error& e) {
        cout << "Outer catch: " << e.what() << "\n";
    }

    return 0;
}
Q: catch by value or reference?A: Always catch by const reference. Value causes object slicing (derived part lost) and unnecessary copy.
Q: What is catch(...)? A: Catches everything — including non-std throws (int, char*, etc). Always last in the chain.
⚠️ Putting base exception before derived — derived is never caught! Order: specific → general.

16.3 — Custom Dynamic Array (no STL)

▼
Theory

Implements the core behavior of std::vector: heap-allocated, auto-resizing, O(1) amortized push_back. Uses a doubling strategy for the capacity to ensure amortized constant-time insertion.

DynArray — Template Dynamic Array
C++
#include <iostream>
#include <stdexcept>
using namespace std;

// ── DYNAMIC ARRAY (like std::vector under the hood) ───────────────────────
// Manual memory management with resizing
template <typename T>
class DynArray {
    T*   data;       // raw heap pointer
    int  sz;         // current number of elements
    int  cap;        // allocated capacity

    // Grow capacity: allocate new array, copy, free old
    void grow() {
        cap = (cap == 0) ? 1 : cap * 2;   // double the capacity
        T* newData = new T[cap];
        for (int i = 0; i < sz; i++)
            newData[i] = data[i];          // copy existing elements
        delete[] data;
        data = newData;
    }

public:
    DynArray() : data(nullptr), sz(0), cap(0) {}

    ~DynArray() { delete[] data; }

    // ── PUSH BACK: amortized O(1) ─────────────────────────────
    void push_back(const T& val) {
        if (sz == cap) grow();             // expand if full
        data[sz++] = val;
    }

    // ── POP BACK: O(1) ────────────────────────────────────────
    void pop_back() {
        if (sz == 0) throw out_of_range("Array is empty");
        --sz;
    }

    // ── SUBSCRIPT: O(1) ───────────────────────────────────────
    T& operator[](int i) {
        if (i < 0 || i >= sz) throw out_of_range("Index out of range");
        return data[i];
    }

    const T& operator[](int i) const {
        if (i < 0 || i >= sz) throw out_of_range("Index out of range");
        return data[i];
    }

    // ── INSERT at index: O(n) ─────────────────────────────────
    void insert(int idx, const T& val) {
        if (idx < 0 || idx > sz) throw out_of_range("Invalid insert index");
        if (sz == cap) grow();
        for (int i = sz; i > idx; i--)    // shift right
            data[i] = data[i - 1];
        data[idx] = val;
        ++sz;
    }

    // ── ERASE at index: O(n) ──────────────────────────────────
    void erase(int idx) {
        if (idx < 0 || idx >= sz) throw out_of_range("Invalid erase index");
        for (int i = idx; i < sz - 1; i++)   // shift left
            data[i] = data[i + 1];
        --sz;
    }

    int size()     const { return sz; }
    int capacity() const { return cap; }
    bool empty()   const { return sz == 0; }
    T& front()           { return data[0]; }
    T& back()            { return data[sz - 1]; }
};

int main() {
    DynArray<int> arr;

    arr.push_back(10);
    arr.push_back(20);
    arr.push_back(30);
    arr.insert(1, 15);       // 10, 15, 20, 30

    for (int i = 0; i < arr.size(); i++)
        cout << arr[i] << " ";   // 10 15 20 30
    cout << "\n";

    arr.erase(0);            // 15, 20, 30
    arr.pop_back();          // 15, 20

    cout << arr.size() << "\n";     // 2
    cout << arr.capacity() << "\n"; // 4 (doubled from 2)
    return 0;
}
Q: Why double capacity instead of increasing by 1?A: Increasing by 1 each time means O(n) copies per push_back, giving O(n²) total. Doubling gives O(1) amortized — n pushes cost O(n) total because each element is copied at most log₂(n) times.
💡 capacity vs size: capacity = allocated slots, size = elements actually stored.

16.4 — Custom Singly Linked List (no STL)

▼
Theory

Each node holds data + a pointer to the next node. No random access (O(n) to reach index i), but O(1) insert/delete at head. Useful when frequent insertion in the middle is needed and index access is rare.

LinkedList with reverse & search
C++
#include <iostream>
#include <stdexcept>
using namespace std;

// ── SINGLY LINKED LIST ────────────────────────────────────────────────────
template <typename T>
class LinkedList {
    struct Node {
        T    data;
        Node* next;
        Node(const T& v) : data(v), next(nullptr) {}
    };

    Node* head;
    int   sz;

public:
    LinkedList() : head(nullptr), sz(0) {}

    // Destructor: walk list, free all nodes
    ~LinkedList() {
        Node* curr = head;
        while (curr) {
            Node* next = curr->next;
            delete curr;
            curr = next;
        }
    }

    // ── PUSH FRONT: O(1) ──────────────────────────────────────
    void push_front(const T& val) {
        Node* n = new Node(val);
        n->next = head;
        head = n;
        ++sz;
    }

    // ── PUSH BACK: O(n) ───────────────────────────────────────
    void push_back(const T& val) {
        Node* n = new Node(val);
        if (!head) { head = n; ++sz; return; }
        Node* curr = head;
        while (curr->next) curr = curr->next;
        curr->next = n;
        ++sz;
    }

    // ── POP FRONT: O(1) ───────────────────────────────────────
    void pop_front() {
        if (!head) throw out_of_range("List is empty");
        Node* old = head;
        head = head->next;
        delete old;
        --sz;
    }

    // ── REMOVE BY VALUE: O(n) ─────────────────────────────────
    bool remove(const T& val) {
        if (!head) return false;
        if (head->data == val) { pop_front(); return true; }
        Node* curr = head;
        while (curr->next && curr->next->data != val)
            curr = curr->next;
        if (!curr->next) return false;
        Node* toDelete = curr->next;
        curr->next = toDelete->next;
        delete toDelete;
        --sz;
        return true;
    }

    // ── SEARCH: O(n) ──────────────────────────────────────────
    bool contains(const T& val) const {
        Node* curr = head;
        while (curr) {
            if (curr->data == val) return true;
            curr = curr->next;
        }
        return false;
    }

    // ── REVERSE IN PLACE: O(n) ────────────────────────────────
    void reverse() {
        Node* prev = nullptr;
        Node* curr = head;
        while (curr) {
            Node* next = curr->next;
            curr->next = prev;
            prev = curr;
            curr = next;
        }
        head = prev;
    }

    void print() const {
        Node* curr = head;
        while (curr) {
            cout << curr->data;
            if (curr->next) cout << " -> ";
            curr = curr->next;
        }
        cout << "\n";
    }

    int size()   const { return sz; }
    bool empty() const { return sz == 0; }
};

int main() {
    LinkedList<int> list;

    list.push_back(1);
    list.push_back(2);
    list.push_back(3);
    list.push_front(0);
    list.print();       // 0 -> 1 -> 2 -> 3

    list.remove(2);
    list.print();       // 0 -> 1 -> 3

    list.reverse();
    list.print();       // 3 -> 1 -> 0

    cout << list.contains(1) << "\n";   // 1 (true)
    cout << list.size() << "\n";        // 3
    return 0;
}
Q: Linked list vs array?A: Array: O(1) random access, O(n) middle insert. Linked list: O(n) access, O(1) insert at known pointer. Use linked list for frequent front-insertions; array for random access.
⚠️ Forgetting to update the tail pointer or losing the head pointer during traversal — causes a memory leak.

16.5 — Custom Stack (LIFO, no STL)

▼
Theory

Stack = LIFO (Last In, First Out). Only top is accessible. Built here on a linked list — push/pop/top are all O(1). Classic use: bracket matching, undo/redo, function call stack.

Stack + balanced parentheses app
C++
#include <iostream>
#include <stdexcept>
using namespace std;

// ── STACK (LIFO) built on a linked list ───────────────────────────────────
// LIFO = Last In, First Out
// push() / pop() / top() all O(1)
template <typename T>
class Stack {
    struct Node {
        T     data;
        Node* next;
        Node(const T& v, Node* n) : data(v), next(n) {}
    };
    Node* topNode;
    int   sz;
public:
    Stack() : topNode(nullptr), sz(0) {}

    ~Stack() {
        while (topNode) {
            Node* old = topNode;
            topNode = topNode->next;
            delete old;
        }
    }

    // ── PUSH: O(1) — add to top ───────────────────────────────
    void push(const T& val) {
        topNode = new Node(val, topNode);   // new node points to old top
        ++sz;
    }

    // ── POP: O(1) — remove from top ──────────────────────────
    void pop() {
        if (empty()) throw out_of_range("Stack underflow");
        Node* old = topNode;
        topNode = topNode->next;
        delete old;
        --sz;
    }

    // ── TOP: O(1) — peek at top without removing ─────────────
    T& top() {
        if (empty()) throw out_of_range("Stack is empty");
        return topNode->data;
    }

    bool empty() const { return sz == 0; }
    int  size()  const { return sz; }
};

// ── APPLICATION: Balanced Parentheses Checker ─────────────────────────────
bool isBalanced(const string& s) {
    Stack<char> stk;
    for (char c : s) {
        if (c == '(' || c == '[' || c == '{')
            stk.push(c);                    // opening: push
        else if (c == ')' || c == ']' || c == '}') {
            if (stk.empty()) return false;  // no matching opening
            char top = stk.top(); stk.pop();
            if ((c == ')' && top != '(') ||
                (c == ']' && top != '[') ||
                (c == '}' && top != '{'))
                return false;               // mismatched pair
        }
    }
    return stk.empty();                     // balanced if nothing left
}

int main() {
    Stack<int> s;
    s.push(10); s.push(20); s.push(30);
    cout << s.top() << "\n";    // 30
    s.pop();
    cout << s.top() << "\n";    // 20
    cout << s.size() << "\n";   // 2

    cout << isBalanced("(a + [b * {c}])") << "\n";   // 1 (balanced)
    cout << isBalanced("((a + b)")        << "\n";   // 0 (unbalanced)
    return 0;
}
Q: LIFO vs FIFO?A: Stack = LIFO: last pushed is first popped (like a stack of plates). Queue = FIFO: first inserted is first removed (like a line/queue).
💡 Stack applications: 1) Balanced brackets 2) Undo/redo 3) Backtracking 4) Expression evaluation

16.6 — Custom Queue (FIFO, no STL)

▼
Theory

Queue = FIFO (First In, First Out). Built with head (front) and tail (rear) pointers — both enqueue and dequeue are O(1). Classic use: task scheduling, BFS, print spooler.

Queue with front/rear pointers
C++
#include <iostream>
#include <stdexcept>
using namespace std;

// ── QUEUE (FIFO) built on a linked list ───────────────────────────────────
// FIFO = First In, First Out
// enqueue = push_back, dequeue = pop_front — both O(1)
template <typename T>
class Queue {
    struct Node {
        T     data;
        Node* next;
        Node(const T& v) : data(v), next(nullptr) {}
    };
    Node* frontNode;   // remove from here
    Node* rearNode;    // add here
    int   sz;
public:
    Queue() : frontNode(nullptr), rearNode(nullptr), sz(0) {}

    ~Queue() {
        while (frontNode) {
            Node* old = frontNode;
            frontNode = frontNode->next;
            delete old;
        }
    }

    // ── ENQUEUE (push): O(1) — add to rear ───────────────────
    void enqueue(const T& val) {
        Node* n = new Node(val);
        if (!rearNode) {
            frontNode = rearNode = n;   // first element
        } else {
            rearNode->next = n;
            rearNode = n;               // advance rear
        }
        ++sz;
    }

    // ── DEQUEUE (pop): O(1) — remove from front ──────────────
    void dequeue() {
        if (empty()) throw out_of_range("Queue underflow");
        Node* old = frontNode;
        frontNode = frontNode->next;
        if (!frontNode) rearNode = nullptr;   // last element removed
        delete old;
        --sz;
    }

    // ── PEEK front: O(1) ──────────────────────────────────────
    T& front() {
        if (empty()) throw out_of_range("Queue is empty");
        return frontNode->data;
    }

    T& back() {
        if (empty()) throw out_of_range("Queue is empty");
        return rearNode->data;
    }

    bool empty() const { return sz == 0; }
    int  size()  const { return sz; }
};

int main() {
    Queue<string> q;
    q.enqueue("Alice");
    q.enqueue("Bob");
    q.enqueue("Carol");

    cout << q.front() << "\n";   // Alice (first in)
    cout << q.back()  << "\n";   // Carol (last in)

    q.dequeue();
    cout << q.front() << "\n";   // Bob (Alice removed)
    cout << q.size()  << "\n";   // 2
    return 0;
}
Q: Why maintain both a front and rear pointer?A: Front enables O(1) dequeue; rear enables O(1) enqueue. Without rear you'd have to walk the entire list to find the end.
💡 Queue applications: 1) BFS graph traversal 2) Task scheduling 3) Printer queue 4) Level-order BST traversal

16.7 — Custom Binary Search Tree (no STL)

▼
Theory

BST: for each node, all values in left subtree < node < right subtree. InOrder traversal gives sorted output. Average O(log n) for insert/search/delete. Degrades to O(n) for sorted input (degenerate tree). Balanced variants (AVL, Red-Black) fix this.

BST with insert / search / delete / inOrder
C++
#include <iostream>
#include <string>
using namespace std;

// ── BINARY SEARCH TREE ────────────────────────────────────────────────────
// Property: left < node < right (for every node)
// Average: insert/search/delete all O(log n)
// Worst case (sorted input): degrades to O(n) — like a linked list

template <typename T>
class BST {
    struct Node {
        T     data;
        Node* left;
        Node* right;
        Node(const T& v) : data(v), left(nullptr), right(nullptr) {}
    };
    Node* root;

    // ── Private recursive helpers ──────────────────────────────
    Node* insert(Node* node, const T& val) {
        if (!node) return new Node(val);    // empty spot found
        if (val < node->data)
            node->left  = insert(node->left,  val);  // go left
        else if (val > node->data)
            node->right = insert(node->right, val);  // go right
        // val == data: BST has no duplicates (ignore)
        return node;
    }

    bool search(Node* node, const T& val) const {
        if (!node) return false;
        if (val == node->data) return true;
        return (val < node->data)
            ? search(node->left,  val)
            : search(node->right, val);
    }

    // InOrder traversal: Left → Root → Right → sorted output
    void inOrder(Node* node) const {
        if (!node) return;
        inOrder(node->left);
        cout << node->data << " ";
        inOrder(node->right);
    }

    // Find minimum node in a subtree (for delete)
    Node* findMin(Node* node) const {
        while (node->left) node = node->left;
        return node;
    }

    Node* remove(Node* node, const T& val) {
        if (!node) return nullptr;
        if (val < node->data) {
            node->left  = remove(node->left,  val);
        } else if (val > node->data) {
            node->right = remove(node->right, val);
        } else {
            // Found node to delete — 3 cases:
            if (!node->left) {          // Case 1: no left child
                Node* tmp = node->right;
                delete node;
                return tmp;
            } else if (!node->right) { // Case 2: no right child
                Node* tmp = node->left;
                delete node;
                return tmp;
            } else {                   // Case 3: two children
                // Replace with inorder successor (min of right subtree)
                Node* successor = findMin(node->right);
                node->data  = successor->data;
                node->right = remove(node->right, successor->data);
            }
        }
        return node;
    }

    void destroy(Node* node) {
        if (!node) return;
        destroy(node->left);
        destroy(node->right);
        delete node;
    }

public:
    BST() : root(nullptr) {}
    ~BST() { destroy(root); }

    void insert(const T& val) { root = insert(root, val); }
    bool search(const T& val) const { return search(root, val); }
    void remove(const T& val) { root = remove(root, val); }

    void printSorted() const {
        inOrder(root);
        cout << "\n";
    }
};

int main() {
    BST<int> tree;

    int vals[] = {5, 3, 7, 1, 4, 6, 8};
    for (int v : vals) tree.insert(v);

    tree.printSorted();          // 1 2 3 4 5 6 7 8  — sorted!

    cout << tree.search(4) << "\n";   // 1 (found)
    cout << tree.search(9) << "\n";   // 0 (not found)

    tree.remove(3);
    tree.printSorted();          // 1 4 5 6 7 8
    return 0;
}
Q: Why does BST degrade to O(n)?A: If you insert in sorted order (1,2,3,4,...) every node becomes a right child — it's essentially a linked list. Balanced BSTs (AVL, Red-Black) prevent this by rebalancing.
Q: InOrder vs PreOrder vs PostOrder?A: InOrder (L→Root→R): sorted output. PreOrder (Root→L→R): serialize tree. PostOrder (L→R→Root): delete tree safely.
💡 BST delete has 3 cases: (1) no children — just delete, (2) one child — splice it out, (3) two children — replace with inorder successor (min of right subtree).
